# color-viewer 仕様書 (Ver.1)

本ドキュメントは、WordPress外の静的ページとして配置する `color-viewer`（色見本帳ビュアー／共通色選択パーツ）の仕様、ファイル入出力、および外部連携APIインターフェースをまとめたものです。  
全体共通のAPI規約（`cb_` プレフィックス等）については、ルートディレクトリの [`api_specification.md`](../api_specification.md) を参照してください。

---

## 1. 概要・配置構成

WordPress上のシミュレーション系ツール（`along-lines-calc`, `cross-base-calc`, `square-color` 等）の色選択箇所から呼び出し、ブラウザ（`localStorage`）に保持した手持ちのバンド色ラインナップから色を選ぶための軽量パーツです。単体で `.XML` / `.CBMESH` の色見本帳ビュアーとしても利用できます。

- **公開URL**: `https://labo.com/CraftBand/nowp-pages/color-viewer.html`
- **関連ファイル（同フォルダ配置）**:
  - `color-viewer.html` : 本体（外部ライブラリ依存なし・単一HTML）
  - `CRAFTBANDMESH-template.CBMESH` : `.CBMESH` 保存用テンプレート（保存実行時のみオンデマンド取得）

---

## 2. 動作モード（呼出し元による自動判定）

URLクエリに **`cb_req_id` または `cb_slot` が含まれるか** で、動作モードを自動判別します。

| 項目 | 色選択モード（別画面からの呼出し） | 単体表示モード（URL直開き・ビュアー用途） |
| :--- | :--- | :--- |
| **判定条件** | `cb_req_id` または `cb_slot` が指定されている | 上記パラメータがいずれも未指定 |
| **左上ボタン** | `キャンセル`（元画面へキャンセル通知して閉じる） | `閉じる`（`window.close()` を試行） |
| **件数・案内表示** | `タップで選択、元画面へ`（0件時は `0色`） | `全〇〇色` |
| **カードタップ** | 元画面へ色を返却して閉じる | 選択・終了は行わない |

## 3. 画面・機能仕様

### 3.1 ヘッダー・レイアウト
- **1行目（コンパクトバー）**: `[キャンセル / 閉じる]` → `[読込・保存 ▼]` → `バンドの種類名 (製品情報)`
  - カッコ内は `tblバンドの種類` の `f_s製品情報` に値がある場合のみ表示（空ならカッコごと非表示）。
- **折りたたみ管理パネル（`読込・保存 ▼`）**:
  - 通常時および読込完了時は閉じて色カードを画面いっぱいに表示（0件かつ `cb_file_url` 未指定時のみ自動展開）。
  - 内部構成：`新規読込` / `追加読込` / バンドの種類名入力欄 / `保存 (.CBMESH)`、および手動追加行（カラーピッカー・色名・製品情報・`追加`）。
- **ソートバー**: `類似色順` / `名前順` / `製品情報順` ＋案内テキスト（左寄せ配置）。
  - **類似色順**: 色相15°バケット $\to$ 明度差（閾値 0.02） $\to$ 色相 $\to$ RGB順。
  - **名前順**: 日本語ロケール（`ja`）昇順。
  - **製品情報順**: 数値考慮の自然順（空は末尾、同値は名前順）。
- **色カードグリッド**: `minmax(108px, 1fr)` の多列グリッド（スマホでも複数列で一覧表示）。各カード右上に削除ボタン（`×`、`confirm('削除してよいですか？')` 付き）。

### 3.2 ファイル読込（`.XML` / `.CBMESH`）
- **対象テーブル**: `tbl描画色`（`f_s色`, `f_sバンドの種類名`, `f_i赤`, `f_i緑`, `f_i青`, `f_i透明度`, `f_s製品情報`）および `tblバンドの種類`（`f_sバンドの種類名`, `f_s製品情報`）。
- **システム色除外**: `f_i透明度 <= 10`（未指定は `255` 扱い）のレコード（「線のみ」等の作図用システム色）は自動除外。
- **複数バンド対応**: `f_sバンドの種類名` が1件なら即適用、複数なら選択モーダルを表示。
- **2つの読込モード**:
  - **新規読込**: 既存の色一覧を全クリアして入れ替え。バンドの種類名・製品情報も更新。不正ファイル時は保存データをクリア。
  - **追加読込**: 既存の色一覧・バンド情報をクリアせず色のみ追加。**既存と RGB・色名・製品情報がすべて一致するレコードはスキップ**（0件時のみバンド名・製品情報を引き継ぎ。不正ファイル時も既存データは保持）。

### 3.3 手動色追加
- カラーピッカーで色を指定し、任意の色名・製品情報を入力して追加（色名未入力時は `#RRGGBB` 形式）。
- 既存と同名の場合は上書き更新。
- 追加直後のみ対象カードを**一覧の先頭に強調表示**し、次の操作（ソート変更・削除・読込・保存・バンド名変更）で現在のソート順に戻す。

### 3.4 `.CBMESH` 保存（テンプレートベース出力）
- 「保存 (.CBMESH)」押下時のみ、同フォルダの `CRAFTBANDMESH-template.CBMESH` を `fetch`（取得後はページ内でメモリキャッシュ）。
- 名前空間 `http://tempuri.org/dstMasterTables.xsd` を維持して以下を更新・生成し、`CraftBandMesh-<バンド種類名>.CBMESH`（UTF-8）をダウンロード：
  - `tblバンドの種類`: `f_sバンドの種類名`、`f_s色リスト`（カンマ区切り）、`f_s製品情報` を更新。
  - `tbl描画色`: 既存レコードを除去し、現在の色一覧（同名重複排除）を出力。
- **テンプレート（`CRAFTBANDMESH-template.CBMESH`）の必須条件**（デスクトップアプリ互換）：
  1. `tbl基本値` が1レコード存在すること（スキーマ既定値・レコード値ともに `f_sバージョン=1.8.5`、`f_s識別情報="color-viewer"`）。
  2. `tblバンドの種類` が少なくとも1レコード存在すること（`f_sバンドの種類名="default-band"`）。
  3. 上記以外のテーブルは空で可。

## 4. ブラウザ永続化（`localStorage`）

同一オリジン（`https://labo.com`）配下のツール群と共有されます。プライベートブラウズ等の制限時は例外を捕捉して画面操作を継続します。

| キー名 | 内容 |
| :--- | :--- |
| `craftband_color_viewer_colors_v1` | 現在保持している色一覧（JSON配列） |
| `craftband_color_viewer_sort_v1` | ソート順（`similar` / `name` / `product`） |
| `craftband_color_viewer_band_name_v1` | 現在のバンドの種類名（規定値: `default-band`） |
| `craftband_color_viewer_band_product_info_v1` | 現在のバンドの製品情報（`tblバンドの種類.f_s製品情報`） |
| `craftband_color_viewer_bridge_event_v1` | 呼出し元へ返却する選択・キャンセルイベントの一時受渡し |

## 5. 外部連携 API 仕様

### 5.1 URLクエリパラメータ

| パラメータ名 | 型 | 必須 | 説明 |
| :--- | :--- | :---: | :--- |
| `cb_req_id` | 文字列 | 任意 | 呼出しリクエストの一意識別子。返却メッセージにそのままエコーバックされ、多重経路での重複受信防止・照合に使用。 |
| `cb_slot` | 文字列 | 任意 | 呼出し元の色スロット識別子（例: `colorA`, `colorB`, `main` 等）。返却メッセージにそのままエコーバックされる。 |
| `cb_file_url` | URL文字列 | 任意 | 初期表示時に自動読込する `.XML` / `.CBMESH` のURL（`http:` / `https:` のみ許可、同一オリジンまたはCORS許可先）。複数バンドがある場合は先頭バンドを適用。 |

※ `cb_req_id` または `cb_slot` のいずれかが指定されていれば「色選択モード」になります。

### 5.2 呼出し元への返却プロトコル

色選択またはキャンセル時、以下の同一オリジン向け経路すべてへ同時に送信し、`window.close()` を試行します（ブラウザごとの挙動差を吸収する多重フォールバック構成）：

1. `window.opener.postMessage(message, window.location.origin)`（別タブ／別ウィンドウ呼出し）
2. `window.parent.postMessage(message, window.location.origin)`（`iframe` 埋込呼出し）
3. `BroadcastChannel("craftband_color_viewer_channel_v1").postMessage(message)`
4. `localStorage.setItem("craftband_color_viewer_bridge_event_v1", JSON.stringify(message))`（`storage` イベント経由）

#### 返却ペイロード：色選択時
```json
{
  "type": "COLOR_VIEWER_SELECT",
  "color": "#d3142d",
  "name": "あかべに 赤紅",
  "productInfo": "001F-21011/15011/06011",
  "cb_req_id": "colorA_1732500000000_ab12",
  "cb_slot": "colorA",
  "sentAt": 1732500012345
}
```

#### 返却ペイロード：キャンセル時
```json
{
  "type": "COLOR_VIEWER_CANCEL",
  "cb_req_id": "colorA_1732500000000_ab12",
  "cb_slot": "colorA",
  "sentAt": 1732500012345
}
```

### 5.3 呼出し側ツール実装時の要点
- `window.open()` を使う場合、Safari での再オープン対策として一意のウィンドウ名・サイズ指定なしを推奨（例: `test-color-viewer.html` 参照）。
- `message` イベント受信時は必ず `event.origin === window.location.origin` を検証する。
- 多重経路から同一メッセージが届くため、呼出し時に発行した `cb_req_id` でリクエスト照合および重複排除を行う。
- `storage` イベントで受信した後は `localStorage.removeItem("craftband_color_viewer_bridge_event_v1")` で後始末を行う。
